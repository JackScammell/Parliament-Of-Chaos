# Parliament of Chaos v1.21.0 — Release Plan

## Goal

Ship a documentation-correctness + bounded-telemetry patch release driven by the
2026-05-15 changelog review (Claude Code v2.1.129 → v2.1.142). The release contains
exactly **one mandatory correctness fix** (P1, data-loss documentation defect) and
**three bounded P2 doc/telemetry items**. No new commands, no new agents, no
settings.json policy change. Scope is deliberately small because 143 of ~150 upstream
changes had no Parliament surface, and the deliberation panel (6/6 APPROVE, 3 rounds)
explicitly resisted scope creep.

## Reuse Decision

- **EXTEND** `.claude/rules/agent-standards.md` — rewrite the existing blockquote in place.
- **EXTEND** `src/hooks/log_event.sh` — add two fields using the existing additive
  `jq` fragment idiom; no new branches, no new files.
- **EXTEND** `commands/parliament-metrics.md` — add the hook-emitted `effort.level`
  source to the existing attribution paragraph.
- **EXTEND** `commands/parliament-loop.md`, `commands/parliament-monitor.md`,
  `commands/cost-report.md` — add targeted doc notes to existing Notes/behaviour
  sections.
- **CREATE**: nothing. Confirms the deliberation's "no new surface" constraint and the
  project-wide extend-don't-create default.

## Options Considered

- **Option A — Ship P1 only, defer all P2 to a later cycle.**
  Pros: smallest possible patch, fastest. Cons: the P2 telemetry item
  (`effort.level` + `agent_id` in `log_event.sh`) is cheap, additive, and unblocks
  accurate `/parliament-metrics --by-effort` attribution for hook-emitted events; the
  three doc-accuracy items are near-zero-risk and already analysed. Splitting them out
  costs a second release cycle for no safety benefit.
- **Option B — Ship P1 + all four P2 items in one v1.21.0 patch.** *(recommended)*
  Pros: single coherent "changelog-review v2.1.129–v2.1.142 adoption" release;
  all items already deliberated and APPROVED 6/6; bounded and additive. Cons:
  slightly larger diff than a pure hotfix.
- **Option C — Fold P1 silently into an unrelated next feature release.**
  Pros: no dedicated release overhead. Cons: a data-loss documentation correction
  must be discoverable in the CHANGELOG on its own line; burying it under an
  unrelated feature heading is exactly the failure mode the review called out.
  Rejected.

## Recommended Approach

**Option B — a single v1.21.0 patch release** titled around the v2.1.129–v2.1.142
changelog adoption, leading with the P1 correctness fix. Semver: this is a
**minor** bump (1.20.0 → 1.21.0) consistent with prior changelog-adoption releases
(v1.16.0/v1.17.0 were minor for feature-adoption batches), even though the headline
item is a doc correction — it changes documented operational guidance materially
enough that users acting on the old note risk losing unpushed commits. The P1 must
appear as the first, clearly-labelled CHANGELOG bullet so it is independently
discoverable; it is not buried under the telemetry item.

## Risks & Trade-offs

- **P1 is the load-bearing item.** The current note tells users to treat v2.1.128 as
  the safe floor. On Claude Code ≥ v2.1.133 the `worktree.baseRef` default flipped
  back to `fresh` (origin-based), so a worktree-isolated specialist spawned from a
  local feature branch with unpushed commits can silently drop that work. The rewrite
  must state: safe configuration is **v2.1.133 + explicit `worktree.baseRef: "head"`**,
  not v2.1.128 alone. Parliament does **not** ship `worktree.baseRef` in settings.json
  (no-policy stance reaffirmed in the v1.14.0 audit) — the note guides the *user* to
  set it; it does not prescribe it. Conflict-priority: this is correctness/data-loss,
  the highest non-security tier — it ships this cycle, not next roadmap.
- **`log_event.sh` is a hot-path script.** Every hook invocation runs it. The
  curmudgeon constraint from the deliberation stands: **additive `jq` only, no new
  control flow, `// "unknown"` / `// empty` fallbacks, consumers must tolerate absent
  fields.** Mirror the existing `duration_ms` conditional-merge pattern; do not add a
  new `case` branch. Recommend `/roadmap-item-scope` before implementing this one
  item so the hot-path change gets an explicit spec and a before/after JSONL sample.
- **Doc-accuracy items are near-zero risk** but must be precise about version floors
  (v2.1.140 for the `/loop` self-notify wakeup change; `claude plugin details` token
  projection landed v2.1.139). A wrong version number in a correction is its own defect.
- **Version-sync risk.** v1.21.0 must be bumped consistently across `plugin.json`,
  `marketplace.json`, `CHANGELOG.md`, and any README/`docs/usage.md` count/version
  anchors (per the recorded release-process feedback). `/cut-release` /
  `/plugin-upgrade` should drive this, not hand edits.
- **No new command/agent/settings surface** — keeps `/parliament-doctor` manifest
  reconciliation and `/settings-audit` clean; no permission policy change.
